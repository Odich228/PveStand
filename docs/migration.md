# Переход со старой версии

Старая версия не сохраняла журнал владельца и могла переиспользовать ВМ по имени. Новая не принимает такие ВМ, пользователей и пулы под управление автоматически.

1. Сохраните старый конфиг, бинарник и резервные копии нужных ВМ.
2. Соберите новый бинарник под другим именем: `go build -o pvestand-new .`.
3. Для проверки выберите новый name/pool, имена ВМ и логины. Внешние bridges можно использовать существующие.
4. Выполните validate, doctor и plan. Проверьте список создаваемых ресурсов.
5. Разверните небольшой тестовый стенд. Проверьте повторный запуск после остановки программы, snapshot, reset и destroy.
6. Сохраняйте новый каталог состояния. Для старых стендов используйте ручное управление либо старую версию после проверки её плана удаления.

Не добавляйте метки вручную и не редактируйте журнал для присвоения чужих ресурсов. Автоматическая миграция требует отдельного режима принятия конкретных VMID с проверкой всех объектов и в этот выпуск не входит.

Существующий `stand-clean` теперь сохраняется. Для смены базовой точки удалите старый снапшот явно в Proxmox, убедившись, что он больше не нужен, и вызовите snapshot снова.
